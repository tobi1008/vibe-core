H1Chờ rollout & ổn định bỏ qua khi ②
wait_for_rollout() · wait_for_stability()
  • kubectl rollout status mỗi 15s, tối đa 600s (đủ cho lần đầu kéo image lớn)
  • Pod đang ContainerCreating → chờ tiếp
  • Gặp ImagePullBackOff, ErrImagePull, CrashLoopBackOff, CreateContainerConfigError… → dừng sớm
  • Rollout xong → chờ thêm 20s: container restart / crash / số Pod Ready tụt → coi là không ổn định
H2Thu thập bằng chứng
collect_workload() · collect_events() · read_build_log_tail()
  • Workload: replicas / readyReplicas, revision hiện tại
  • Từng Pod: phase, condition chưa True, trạng thái container, số lần restart, lần terminated trước
  • Log container (60 dòng cuối) + log lần crash trước (--previous), đã che secret
  • 20 sự kiện K3s gần nhất của app · 80 dòng cuối log build (lọc dòng tiến trình docker)

H5Hợp nhất kết luận — K3s là căn cứ cuối
verify_deployment()
  • ready = có workload ∧ không có error ∧ mọi rollout ở H1 đều Ready
  • ready → healthy (bất kể AI nói gì)
  • chưa ready + AI trả status hợp lệ → dùng status của AI (AI chỉ tinh chỉnh tầng lỗi)
  • ngược lại → dùng fallback_status của H3; nếu H3 ra healthy mà chưa ổn định → hạ về starting
  • AI không thể biến lỗi thành healthy
H4Hỏi Hermes LLM AI
ask_hermes() → run_hermes_json()
  • Prompt = kết quả H1 + snapshot H2 + phân loại sơ bộ H3, yêu cầu “chỉ dựa vào bằng chứng”
  • Hermes API gateway (OpenAI-compatible), thử lần lượt tối đa 3 model mã nguồn mở, mỗi model 45s, đổi model khi 429 / lỗi
  • Chỉ được chọn status trong danh sách cho phép:
    ② → build_error pipeline_error k8s_config_error code_error
    ①③ → code_error k8s_config_error starting healthy
  • Trả JSON: status · summary · evidence[] · suggestions[]
